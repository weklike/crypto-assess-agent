## 已写入的三种编号

1. **测评单元／通用条款号**，例如 `GB/T 43206-2023#6.1.2`。
2. **测评指标号**，例如 `GB/T 43206-2023#6.1.2.1`；单元和指标不是同一个切分粒度。
3. **基本要求的位置**，按等级分列，例如第三级的 `GB/T 39786-2021#8.1 b)`。其中`b)`是条内字母列项，**不是`8.1.2`**。第一级、第二级、第四级另列真实章节，不将所有问题默认定为三级。

`GB/T 43206-2023`按测评单元组织，`GB/T 39786-2021`中一级至四级要求分别位于第6至第9章。两者不能套用同一套条款编号。

每条问题都给出标准号及可回查的链接。问句本身仍是上一版的合成问题；“标准来源”表示关联的标准依据，**不表示问句原文摘自该标准**。

## 核对依据与限制

S01、S02为国家标准全文公开系统中的标准元信息；S03为江苏省密码管理局公开的GB/T 39786-2021原文PDF，本次使用页面图像核对章节及字母列项。

S04为四川省密码管理局发布GB/T 43206-2023的页面。该页的标准PDF本次未成功读取。因此，**没有声称对GB/T 43206-2023原文PDF逐页完成了核对**。对应测评指标编号主要依据中国密码学会密评联委会《商用密码应用安全性评估测评实施指引》（2024年11月）中的明确交叉引用核对（S05）。例如指引8.1.1明确引用标准6.1.1.1、6.1.2.1、6.1.3.1；指引9.2.3.1引用标准7.2.3.1。目录中列明每个编号的核对位置，指引编号没有冒充国家标准编号。

S05 PDF可取得带页码文本，但本次截图服务未成功渲染该文件。故其页码和交叉引用是文本核对结果，不记为页面视觉核对结果。交付只保留编号、标题和自拟映射说明，不附标准或指引正文。

**编号存在性与问句相关性是两项不同工作。** 已找到标准编号不等于某个情景已经获得完整答案，更不等于项目数据库中已有同名记录。共享机房责任、透明加密与DBA权限、签名法律效力、应急关闭加密等问题的支持范围有限，均在逐题说明中保留了限制。

## 不同关联如何使用

- `直接对应`：主题与单元直接对应，但仍需本地核对具体指标和证据。
- `多条联合`：同一问题涉及多个方面，列出多个主要候选。
- `需场景确认`：问题未明确数据状态、身份主体或对象边界等，候选可能互为替代；**不能直接把所有候选都当成必须同时命中的gold**。
- `部分支持`：标准能支持技术或管理方面的一部分问题，但不能完整回答责任、法律效力或特定实现等问题。

补充／条件性依据没有自动加入7字段版本的`gold_refs`。这避免只要主题有关，就把所有通用条款与所有等级条款统统塞进正式标签。

第5章通用要求和资料性附录不是第6、7章的独立技术／管理计分单元。附录B的密钥生成、分发、存储、使用、更新、归档、撤销、备份、恢复、销毁使用原有字母列项定位，不编造B.1—B.10。

## 与项目数据集衔接

保留现有正式`retrieval_queries.v1.jsonl`，不要直接覆盖。建议先把候选文件放在草稿目录进行人工审核。

1. 在本地已规范化的两份标准及`kb_clause`中核对编号和正文。
2. 对照本地切分粒度选择真实引用。例如，数据库可能只有`#6.1.2.1`及`#6.1.2.3`叶条款，而没有`#6.1.2`父单元；也可能采用相反规则。此次没有得到你项目中的规范化结果，不能猜测其主键。
3. 若问题问的是证据或核查方法，应核对并选择实际已入库的测评对象、测评实施等子条款；本次的指标号不能替代对整道问题的支撑判断。不要无条件给所有单元追加`.3`。
4. `level`保持原文件的`null`。需要等级过滤时，先明确问题适用的等级，再选对应基本要求。表中“该级未列同名专项要求”不等于某一实际项目可以直接判不适用；还要考虑密码应用需求和方案。
5. 跨层面的密钥、人员、应急等引用可能被项目的层面过滤排除。原`layer`仅为原始问题分类；本次未改动它。形成正式标签时需决定：拆题、调整过滤口径，或只选当前检索范围可达的引用。不要把永远无法检索到的跨层面条款计入召回率分母。
6. 人工确认实际相关引用后，再转成正式v1数据集并运行项目现有校验器：

```bash
java -jar target/crypto-assess-agent-0.0.1-SNAPSHOT.jar \
  --spring.profiles.active=eval \
  --eval.tool=validate \
  --eval.dataset=v1
```

以上命令来自上传的实施计划；本轮没有运行你的应用、数据库或该校验器。
