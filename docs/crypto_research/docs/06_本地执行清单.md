# 本地落地清单：从研究候选到正式评测

以下命令来自上传方案，仅供所有者在项目根目录核对后执行。本次没有运行它们。不得把本研究包的candidates直接改名充当正式数据。

## A. 开始前的两个决定

先确认规则语义：8/8/8/6、技术对象平均、D/A/K、单元权重和不适用处理。再确认数据处理边界：原文保持本地时，使用本地模型；外部API只在授权与许可范围明确后考虑。不得把真实API key写入研究报告、git或聊天。

## B. 标准原文与规范化

在所有者本机按已登记官方入口取得两份标准，放到data/raw，记录文件SHA256、来源、日期与使用授权。按原项目NormalizeTool执行sha256、draft、lint；参数具体顺序以现有工具实际实现为准。上传方案示意如下：

```text
java -cp target/classes com.cryptoassess.knowledge.tool.NormalizeTool sha256 <本地PDF路径>
NormalizeTool draft <PDF> "<标准号>" "<标题>"
NormalizeTool lint <规范化文件>
```

若工具用到外部依赖，只有target/classes可能不足，需要真实运行时classpath；不要根据本清单推断工具已经无依赖。生成稿核对前言、目录、章号、表格、字母项、附录和元数据。使用worksheets目录的50条抽查及要求覆盖表。

导入和重建API的请求体、鉴权头并未随本次文件提供完整契约；从仓库README/控制器确认后再调用。不要用猜测的curl请求体提交。

## C. 检索集标注

先核查drafts候选，填正确gold和必要等级，再用项目工具逐条追加正式数据。原计划命令为：

```bash
java -jar target/crypto-assess-agent-0.0.1-SNAPSHOT.jar \
  --spring.profiles.active=eval --eval.tool=annotate --eval.dataset=v1
```

标注确认后再运行同一jar的 `--eval.tool=validate --eval.dataset=v1`。运行前确认jar实际名称、启动参数和数据库指向，保留命令、退出码和结果摘要。抽查10条。主题组不要跨调参/测试划分。

## D. 题库本地转换

只在data/private中保存原件和导出文本；先核附件真实格式和题量。按上传方案整理题型标题、题号、选项、答案行，然后：

```bash
./mvnw -q compile dependency:build-classpath -Dmdep.outputFile=target/classpath.txt
CP="target/classes:$(cat target/classpath.txt)"
java -cp "$CP" com.cryptoassess.eval.qabank.QaBankTool convert \
  data/private/qa_bank.txt data/private/qa_bank.jsonl
java -cp "$CP" com.cryptoassess.eval.qabank.QaBankTool sample \
  data/private/qa_bank.jsonl data/private/qa_bank_sample.v1.jsonl 200 20260924
```

这是Linux/WSL shell的classpath写法；Windows原生需要使用该环境的路径分隔。工具不覆盖输出，修复错误后不要无备份删除原始数据。先完成20题抽查再接受抽样结果；保存每题型数量和文件哈希。使用git check-ignore/git status核查私有路径没有被追踪，同时检查模型与追踪出口，不能只检查git。

## E. 评分和模拟系统

读取实际rules/scoring.v1.yaml、rules/algorithms.v1.yaml、评分器和systems/README后再改。若与官方规则不一致，明确升级为新版本并保留旧报告的规则指纹。

drafts/scoring_arithmetic.review-candidates.yaml不是可执行golden。所有者复核数值和适用假设后，再按正式schema构造至少30个用例；没有数据契约支持的D/A/K、分组和权重，不用虚构字段凑数。零分母候选不计入35个数值用例，也不能设定任意分数。

所有者根据12张研究卡编写10—15个模拟系统，至少3个明确的电力关基假设；独立填写每项预期差距及理由，并补全其余符合/不适用/缺证据的人工检查记录，防止expected漏项造成误报失真。

## F. 冻结及正式运行

先在开发数据上决定topN、拒答阈值、词典和超时；之后填写worksheets/评测冻结清单.yaml。确认数据许可、真实模型映射、报价和汇率，最后运行现有retrieval、qa、gap、scoring、summary。T22不得改数据/阈值/提示词。

正式报告要包含失败数、超时数和拒答数，不能只统计成功调用。保存索引/数据/规则/代码/环境指纹。然后再更新PROGRESS正式结果及简历数字；本次研究结果不能代替这些性能数值。
