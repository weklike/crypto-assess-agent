# 演示脚本（3–5 分钟）

录屏前准备：core profile 全部 healthy、`/api/health` 全部 UP、标准已导入并建索引、至少准备 1 个模拟系统。

| 时间 | 画面 | 讲什么 |
| --- | --- | --- |
| 0:00–0:30 | README 架构图 | 密评是什么、为什么需要辅助自查；系统分三块：检索问答、评估工作流、确定性规则 |
| 0:30–1:15 | 检索调试页 | 同一个口语问题在四种模式下的结果；指出 BM25 名次、向量名次、RRF 分、重排分和各阶段耗时 |
| 1:15–2:15 | 问答页 | 流式输出；点开引用卡片看条款原文；演示一个低相关问题被拒答；说明无效引用会被剔除 |
| 2:15–3:45 | 评估项目页 | 新建项目 → 录入测评对象和密码措施（故意包含一个非认可算法）→ 开始分析并轮询 → 差距项里出现“规则改判” → 修改一条判定、写备注、全部确认 → 自动评分 → 下载 Word 报告，指出封面的“辅助自查草稿，需测评人员确认” |
| 3:45–4:30 | 终端 | MCP Inspector 列出 4 个工具并调用 check_algorithm；无 Key 调用返回 401；查询 audit_log 只有参数哈希 |
| 4:30–5:00 | 评测报告 | 打开 `eval/results/…-summary/report.md`：检索四种模式、问答三组、差距识别两种方案的对比数字，每个数字都能追到子报告 |

讲解要点：模型只做理解和表达，合规与评分是确定性代码；失败显式、不静默降级；每个数字都有评测报告支撑。
