# 面试问题与参考回答

以下回答基于本仓库的实现与 `docs/decisions.md` 的取舍；涉及评测数字的问题，以 `eval/results/` 下的正式报告为准，没测出来的不说。

1. **为什么融合放在应用层、用 RRF 而不是分数加权？**
   BM25 分数与余弦相似度量纲不同、分布随查询变化，直接加权需要调参且不稳定。RRF 只看名次：score = Σ 1/(k + rank)，k=60 让靠前名次的差距不至于过大。放在应用层可以拿到每一路的名次和分数，调试页和评测共用同一份数据；同分按 BM25 名次优先，保证结果确定。

2. **引用校验怎么做，为什么在流式结束后才校验？**
   `CitationParser` 兼容全角括号、多余空格、长短破折号和同一括号内的多个引用，规范化成 `标准号#条款号`；`CitationValidator` 只认本次检索结果里的条款，知识库里存在但不在本次结果中的也算无效（模型没看到原文）。流式片段可能把一个引用切成两半，所以在全文结束后统一校验，再发 citations 事件。

3. **大模型输出不合规怎么办？为什么不重试？**
   结构化输出先经过 Spring AI 的 StructuredOutputValidationAdvisor（重试次数设为 0），再用同一份 JSON Schema 显式校验，失败抛 `LLM_INVALID_OUTPUT` 并把 `llm_call.status` 记为 INVALID_OUTPUT。advisor 默认会带着错误信息重新调用模型，属于隐藏重试，既花钱又让评测不可复现；重试次数为 0 时它校验失败只打警告，所以必须再加一层显式校验。

4. **为什么合规判断和评分不交给大模型？**
   这两件事有明确规则，需要可复现、可解释、可版本化。规则表和评分规则都是 YAML，代码不写死任何算法结论；评分用 BigDecimal、只在输出时舍入一次，assess_score 记录 rule_version，规则更新后旧报告能按原版本复现。评分按官方量化评估规则的 D/A/K 计分：模型列出的相关算法被规则判为不合规时，代码把 A 强制为“不满足”（得分 0.5·Ra，Ra 由算法安全强度查表），并明确标注，而不是静默兜底；某组全部不适用时不出总分，转人工。

5. **工作流的断点续跑怎么实现？模型调用为什么不能放在事务里？**
   步骤粒度是“对象 × 测评指标”，唯一键 (project, object, step, step_key)；每步开始写 RUNNING，成功时在一个短事务里同时写差距项和步骤结果，再次分析时跳过已成功的步骤。模型调用可能几十秒，放在事务里会长时间占用连接和行锁，失败回滚还会丢掉已经付费得到的结果。进程重启后把遗留的 RUNNING 标记为失败再续跑。

6. **Kafka 至少一次投递下怎么保证幂等？死信怎么处理？**
   `ingest_job` 以 (normalized_sha256, parser_version) 为唯一键；消费者先查任务是否已成功，再用条件更新 claim，已成功的重复消息直接确认；入库本身也按内容哈希幂等。失败按指数退避重试 3 次后进 `kb.ingest.v1-dlt` 并标记 FAILED，格式错误这类重试无效的直接进死信。修复原因后重新提交，FAILED 任务会重新排队。

7. **令牌桶为什么用 Lua？**
   “读余量 → 按时间补充 → 扣减 → 写回”必须原子，否则并发请求会超发。Lua 脚本在 Redis 里单线程执行，用 Redis 服务器的 TIME 避免多实例时钟不一致；桶在装满所需时间之后过期。集成测试里 20 个并发请求、容量 5，恰好放行 5 个。

8. **MCP 和 Function Calling 有什么区别？怎么防工具投毒和权限扩大？**
   Function Calling 是某个模型 API 内的工具声明；MCP 是独立的协议，工具由服务器提供、任何 MCP 客户端都能发现和调用。这里工具描述写死在代码里、不从数据库或配置加载，不聚合第三方 MCP 服务器；API Key 只存哈希、按 scope 授权，所有工具共用 /mcp，所以在过滤器里解析 JSON-RPC 请求体按工具名检查 scope，不足返回 403 并审计；工具全部只读、返回内容限长。

9. **为什么外部依赖不可用时返回 503 而不降级？**
   静默降级（比如重排挂了退回混合检索、缓存挂了绕过缓存）会让线上行为和评测结果不一致，用户也不知道结果质量变了。显式失败配合 `/api/health` 的逐项检查，问题能被立刻发现；是否降级应该是明确的产品决策，而不是代码里的隐藏分支。

10. **评测怎么保证可信？**
    评测集带版本号，修正时新建版本并记录原因，不为提分改题目、标注或阈值；每次运行写到新的时间戳目录，已存在就报错，失败也保留；报告写明 git commit、模型、提示词版本、数据集版本和哈希、检索参数、样本数；题库相关输出只有题号和对错。全量评测在同一个 commit 上依次重跑，总报告链接每个子报告。
