## 1. 用 Claude Code 推进的方法

### 1.1 每个任务的节奏

1. 新开一个会话（或 `/clear`），一个会话只做一个任务。
2. 按 Shift+Tab 切到 Plan Mode，发送 1.2 的提示词，让 CC 读任务卡后先给计划。
3. 审计划：文件清单、测试清单、待确认问题都回答清楚，再回复“开始”。
4. CC 先写失败的测试再实现，跑验收命令，更新 `docs/PROGRESS.md`，写“讲解”。
5. 你自己看 `git diff`、再跑一遍验收命令、读讲解；能讲清楚再 `git commit`。
6. 讲解里有答不上来的地方，追问 CC 直到弄懂，再开始下一个任务。

### 1.2 提示词模板

```text
按 AGENTS.md 的工作方式执行 docs/实施计划.md 的 T06。
只读任务卡 “### T06” 这一节，不要做其他任务。
补充要求：
- （粘贴任务卡里“CC 提示词要点”的内容）
```

### 1.3 常见情况

| 情况 | 做法 |
| --- | --- |
| Spring AI 2.0 或 Boot 4 的 API 编译不过 | 让 CC 先查官方文档或 `~/.m2` 里的 sources jar 再改，不要降级依赖 |
| 测试反复失败 | 让 CC 列出假设和最小复现，别继续堆代码；30 分钟没进展就停下，把问题记进 PROGRESS.md |
| CC 想顺手改任务外的东西 | 拒绝，记到 PROGRESS.md 的“以后再说” |
| 需要新依赖 | 让 CC 说明理由和替代方案，你同意后再加，并写进 decisions.md |
| 会话上下文太长 | `/compact`，或结束会话，下次从 PROGRESS.md 接着做 |

## 3. 任务卡

### T00 仓库与工程骨架

- **周次**：W0 · 0.5 天 · 依赖：无
- **目标**：能构建、能测试的空工程，目录结构与 AGENTS.md 一致。
- **步骤**
  1. 在 start.spring.io 生成：Maven、Java 21、Spring Boot 4.1.x；依赖选 Spring MVC、Validation、Actuator、MySQL Driver、Flyway、Spring Data Redis、Testcontainers。由你在网页生成后解压到仓库，或让 CC 调用 start.spring.io 的 HTTP 接口生成。
  2. 按官方文档加入 Spring AI 2.0 BOM、`spring-ai-starter-model-openai`、Ollama starter，以及 `mybatis-spring-boot-starter` 4.1.x。
  3. 建包 `common`、`knowledge`、`retrieval`、`qa`、`assessment`、`rules`、`report`、`mcp`、`eval`，每个包放 `package-info.java`，写一行职责说明。
  4. `.gitignore` 加入 `data/raw/`、`data/private/`、`data/normalized/`、`.env`；提供 `.env.example`。
  5. `ApplicationContextIT`：用 Testcontainers 启动 MySQL，确认应用上下文能加载。
- **验收**：`./mvnw -q verify` 通过；新建一个 `.env` 和 `data/raw/x.txt`，`git status` 里看不到它们。
- **CC 提示词要点**：不要凭记忆写 Boot 4 的 starter 名，以生成的 pom 为准；依赖版本交给 BOM 管理。
- **讲解要求**：BOM 管理版本的好处；为什么按功能分包；`@ServiceConnection` 做了什么。

### T01 本地环境与健康检查

- **周次**：W0 · 1 天 · 依赖：T00
- **目标**：`core` profile 一键启动；应用连上全部依赖；`/api/health` 如实报告。
- **步骤**
  1. 确认版本组合：Boot 管理的 Elasticsearch Java 客户端版本 → 选同版本的 ES 服务器 → 确认 `get.infini.cloud/elasticsearch/analysis-ik/<版本>` 存在。三者写进 decisions.md；不一致时在 pom 里覆盖客户端版本。
  2. `deploy/elasticsearch/Dockerfile`：基于官方镜像安装 IK；单节点、仅本机访问时关闭安全认证、堆 1 GB。加自定义词典（密评、商用密码、测评对象、SM2、SM3、SM4 等术语）。
  3. `deploy/compose.yaml`：profile `core`（mysql、redis、elasticsearch、ollama、tei-rerank）、`mq`（kafka）、`obs`（先留空）；端口只绑 `127.0.0.1`；数据卷具名。
  4. Flyway 首个脚本：`kb_document`、`kb_clause`、`llm_call`、`audit_log`，字段见开发计划 §5.2。
  5. `@ConfigurationProperties`：`app.embedding`、`app.rerank`、`app.retrieval`（候选数、RRF 常数、拒答阈值）。
  6. `/api/health`：检查 MySQL、Redis、ES（含 IK 可用：对一段中文调用 `_analyze`，结果不是逐字切分）、Ollama（模型已拉取）、TEI；只检查模型配置是否齐全，不实际调用大模型。任一不可用返回 503 和明细。
- **验收**
  - `docker compose -f deploy/compose.yaml --profile core up -d` 后全部服务 healthy
  - `curl -s 127.0.0.1:8080/api/health` 全部为 UP
  - `IkAnalyzerIT`：自定义词典里的术语被切成一个词
- **CC 提示词要点**：ES 用官方 Java 客户端；compose 和配置文件里不写真实密钥；健康检查不调用大模型。
- **讲解要求**：为什么 ES 服务器、插件、客户端版本要一致；`ik_max_word` 和 `ik_smart` 的区别及各自用在哪；健康检查为什么不调用大模型。

### T02 语料准备与规范化

- **周次**：W0–W1 · 1.5 天（主要是你的人工核对）· 依赖：T00
- **目标**：GB/T 39786-2021、GB/T 43206-2023 转成规范化 Markdown 并通过格式检查。
- **步骤**
  1. 你把原始 PDF 放进 `data/raw/`（官方公开渠道或学校标准库），记录 SHA256。
  2. CC 写提取工具（PDFBox 或 `pdftotext`），生成初稿 `data/normalized/*.draft.md`。
  3. 你逐章核对：修正断行、表格和编号；给“要求”类条款补元数据注释（格式见开发计划 §5.1）。
  4. CC 写 `NormalizedFormatLinter`：编号唯一、层级连续、元数据齐全，输出行号级错误。T03 的解析器会复用它。
  5. 在 `data/fixtures/` 写一份约 20 条的“仿标准”：结构与真实文件相同，内容自拟，供所有测试使用。
- **验收**：两份规范化文件 lint 零错误；你抽查 50 条，与原文逐字一致；fixtures 通过 lint。
- **CC 提示词要点**：`data/raw`、`data/normalized` 的内容不得写进测试、代码注释或文档；表格按“一行一条”转成文本。
- **讲解要求**：为什么不直接解析 PDF；元数据由谁标注、怎么保证质量。

### T03 条款解析与入库

- **周次**：W1 · 1.5 天 · 依赖：T01、T02
- **目标**：规范化文件写入 `kb_document`、`kb_clause`，重复导入不产生重复数据。
- **步骤**
  1. `NormalizedStandardParser`：解析 front matter、标题编号（含附录编号）、元数据注释和正文，输出 `ParsedStandard`、`ClauseRecord`（record）。
  2. 校验失败抛 `NormalizedFormatException`（带行号），整份不入库。
  3. `KnowledgeIngestService.importDocument(fileName)`：计算 normalized_sha256；已导入则直接返回；否则在一个事务里写文档和条款。
  4. MyBatis Mapper（XML）：批量插入条款、按 clause_ref 查询。
  5. 接口：`POST /api/kb/documents`、`GET /api/kb/documents`、`GET /api/kb/clauses?ref=`。
- **验收**
  - 单元测试：fixtures 解析出的条款数、编号、路径、层面、等级全部正确；错误样例报出正确行号
  - 集成测试：同一文件导入两次，条款数不变
  - 真实数据：两份标准导入成功，条款数写进 PROGRESS.md
- **CC 提示词要点**：解析器是纯 Java、不依赖 Spring，先写表驱动测试；说明批量插入方式的选择理由。
- **讲解要求**：幂等键为什么用规范化文本的哈希；单事务导入的好处与代价；附录编号怎么识别。

### T04 向量化与 ES 索引

- **周次**：W1 · 1 天 · 依赖：T03
- **目标**：条款写入 `kb_clause_v1` 并挂上别名 `kb_clause`，可以重建。
- **步骤**
  1. `EmbeddingClient` 接口，默认实现用 Spring AI 的 Ollama `EmbeddingModel`；批量大小和超时可配置。
  2. 向量化文本 = 章节路径 + 标题 + 正文；维度不是 1024 时直接报错。
  3. `ClauseIndexer`：按开发计划 §5.3 从 `src/main/resources/es/kb_clause_v1.json` 建索引，bulk 写入，完成后切换别名。
  4. 管理接口 `POST /api/kb/reindex`（二期加鉴权，当前只在本机使用）。
- **验收**
  - 集成测试（ES-IK 容器 + `FakeEmbeddingModel`）：索引文档数等于条款数；重建后别名指向新索引
  - 真实数据：ES 文档数与 MySQL 条款数一致
- **CC 提示词要点**：不用 Spring Data Elasticsearch 的 Repository；映射只从 JSON 文件读取。
- **讲解要求**：为什么用别名切换；`dense_vector` 的 cosine 与 HNSW；向量化文本为什么要带章节路径。

### T05 检索评测集与标注工具

- **周次**：W1–W2 · 1 天 + 你的标注时间 · 依赖：T04
- **目标**：`eval/datasets/retrieval_queries.v1.jsonl` 至少 80 条，一期结束前补到 150 条。
- **步骤**
  1. 字段：`id`、`query`、`gold_refs`（数组）、`style`（`colloquial` / `paraphrase` / `keyword`）、`layer`、`level`、`note`。
  2. CC 做一个标注小工具（命令行或 eval profile 下的网页）：输入查询 → 显示 BM25 前 20 条 → 你勾选应命中的条款 → 追加到 JSONL。
  3. 可选：让模型根据条款生成候选查询，你筛选改写后再标注，`style` 记为 `paraphrase`。
  4. `DatasetValidator`：`gold_refs` 必须存在于 `kb_clause`；id 唯一；三种问法都有。
- **验收**：validator 通过；三种问法各约三分之一；你抽查 10 条标注无误。
- **CC 提示词要点**：工具只追加不改已有行；标注工具不进生产接口。
- **讲解要求**：为什么标注要覆盖三种问法；合成查询会带来什么偏差。

### T06 四种检索模式

- **周次**：W2 · 2 天 · 依赖：T04
- **目标**：`POST /api/search` 支持 `bm25`、`dense`、`hybrid`、`hybrid_rerank`。
- **步骤**
  1. `SearchRequest(query, mode, k, layer, level)`；`SearchHit(clauseRef, title, snippet, bm25Rank, denseRank, rrfScore, rerankScore)`；响应带各阶段耗时 `timings`。
  2. `Bm25Retriever`、`DenseRetriever` 各取 50 条，过滤条件一致。
  3. `RrfFusion`：纯函数，k 可配（默认 60），按 clauseRef 去重，同分时按 BM25 名次。
  4. `RerankClient` 接口与 `TeiRerankClient`：只重排融合后的前 30 条；TEI 不可用时 `hybrid_rerank` 返回 503，不静默降级。
- **验收**
  - `./mvnw -q test -Dtest='RrfFusionTest'`：覆盖空列表、单路结果、重复条款、并列名次
  - 集成测试：fixtures 上四种模式都有结果，过滤条件生效
  - 手工：5 条真实查询在四种模式下的结果对比记进 PROGRESS.md
- **CC 提示词要点**：先写 `RrfFusion` 的表驱动测试；kNN 用 ES 官方客户端；不用 ES 自带的 rrf retriever，融合放在应用层。
- **讲解要求**：RRF 为什么用名次不用分数、k 起什么作用；BM25 和向量各擅长什么查询；为什么只重排前 30 条；重排服务挂了为什么不降级。

### T07 检索评测运行器

- **周次**：W2 · 1 天 · 依赖：T05、T06
- **目标**：一条命令跑完四种模式并生成报告。
- **步骤**
  1. `EvalRunner`（profile=eval）：参数 `--eval.suite=retrieval --eval.dataset=v1`；跑完退出，退出码 0 表示完成、1 表示运行失败。
  2. `Metrics`：Recall@k、MRR、nDCG@10、P50/P95 延迟；按问法和安全层面分组。
  3. 输出 `eval/results/<UTC 时间戳>-retrieval/`：`report.md`（总表、分组表、最差 10 条）、`metrics.json`、`cases.jsonl`；写 `eval_run`（新增 Flyway 脚本）。
- **验收**
  - 指标函数用手算的小例子做单元测试
  - `./mvnw spring-boot:run -Dspring-boot.run.profiles=eval -Dspring-boot.run.arguments="--eval.suite=retrieval"` 生成报告
  - 报告写明数据集版本、索引版本、embedding 模型、重排模型和 k 值
- **CC 提示词要点**：结果目录已存在就报错、不覆盖；指标自己实现，不引第三方库。
- **讲解要求**：Recall@5、MRR、nDCG 分别衡量什么；为什么要按问法分组看。

### T08 问答：RAG、引用校验、SSE、拒答

- **周次**：W3 · 2 天 · 依赖：T06
- **目标**：`POST /api/qa` 流式回答，引用经过校验。
- **步骤**
  1. 提示词 `prompts/qa-answer.v1.st`：只能依据给定条款；每个结论后标注 `[clause_ref]`；资料不足时直说。
  2. `QaService`：检索 → 拒答判断（阈值来自配置）→ `ChatClient` 流式调用（超时可配）→ 汇总全文。
  3. `CitationParser` 解析 `[GB/T 39786-2021#6.2.1]` 这类引用；`CitationValidator` 只认本次检索结果里的条款。
  4. SSE 事件按开发计划 §6.2；结束时写 `qa_record`（新增 Flyway 脚本）和 `llm_call`。
  5. `FakeChatModel` 按脚本返回：正常、含无效引用、超时、空回复。
- **验收**
  - 单元测试：引用解析（全角括号、多余空格、连续多个引用）与校验（存在、不存在、不在本次结果中）
  - 接口测试：事件顺序为 meta → token… → citations → done；超时返回 error 事件，`llm_call.status` 为 TIMEOUT
  - 手工：5 个真实问题的引用都能打开到条款
- **CC 提示词要点**：提示词文件带版本号；测试不调用真实模型；无效引用不能显示成有效来源。
- **讲解要求**：为什么要校验引用；拒答阈值怎么定；流式输出时引用在什么时候校验。

### T09 题库转换与问答评测

- **周次**：W3 · 1.5 天 · 依赖：T08
- **目标**：题库抽样，完成三组对比评测。
- **步骤**
  1. 你从[官方页面](https://www.oscca.gov.cn/sca/xwdt/2026-03/03/content_1061327.shtml)下载 OFD 题库放进 `data/private/`，用 ofdrw 或 OFD 阅读器导出文本。
  2. CC 写转换脚本，生成 `data/private/qa_bank.jsonl`（`id`、`type`：single / multi / judge、`stem`、`options`、`answer`）；你抽查 20 题。
  3. 按题型分层抽样约 200 题，固定随机种子，写入 `data/private/qa_bank_sample.v1.jsonl`。
  4. 提示词 `prompts/qa-exam.v1.st`：结构化输出 `{answer: ["A"], citations: [...]}`，经 JSON Schema 校验。
  5. `QaEvalSuite`：无检索、hybrid、hybrid_rerank 三组；统计准确率（多选需完全一致）、引用有效率、拒答率、延迟、token 与费用。
  6. 用结果校准 T08 的拒答阈值，写进 decisions.md。
- **验收**：报告生成；`cases.jsonl` 只有题号和对错；你抽 30 题人工核对引用是否支撑答案，结论写进报告。
- **CC 提示词要点**：题目原文不得进入任何 git 跟踪的文件；温度设为 0。
- **讲解要求**：为什么分层抽样；多选题为什么要求完全一致；无检索组说明了什么。

### T19 Kafka 异步入库、Redis 限流与缓存

- **周次**：W7 · 2 天 · 依赖：T04
- **目标**：入库异步且幂等；模型调用限流；向量结果缓存。
- **步骤**
  1. `mq` profile 启动 Kafka；topic `kb.ingest.v1`，消息 key 为 normalized_sha256。
  2. `POST /api/kb/documents` 改为写 `ingest_job`（新增 Flyway 脚本）并发消息，返回 202；消费者负责解析、写库、向量化和索引。
  3. 幂等：`ingest_job` 唯一键（normalized_sha256, parser_version）加状态转换；重复消息直接确认。
  4. 失败按指数退避重试 3 次后进死信 topic，`ingest_job` 记录错误。
  5. Redis：向量缓存（key = 模型名 + 文本 SHA256）；令牌桶限流（Lua 脚本，按 API Key 或会话），超限返回 429。
- **验收**

  - 缓存命中率写进评测报告
- **CC 提示词要点**：用 spring-kafka 的 `DefaultErrorHandler` 和 `DeadLetterPublishingRecoverer`；Lua 脚本单独成文件并有测试。
- **讲解要求**：至少一次投递下怎么做到幂等；令牌桶为什么用 Lua；死信消息怎么处理。
